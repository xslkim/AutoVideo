>>> 片头 #B01
服务器要同时盯住一万个连接
怎么知道此刻，谁有数据来了
这个问题的答案，就是 **Linux** 高并发的标配：**epoll**
这条视频讲清楚三件事
它为什么快、它和你平时写的回调有啥区别、它怎么撑起 **Asio** 这类网络库


>>> 高并发的真问题 #B02
现在看 epoll 要解决的真问题
你的服务器接入了**一万个客户端连接**
每个连接对应一个 socket，也就是一个文件描述符
问题是：这一万个里面，**此刻哪几个有数据来了**
答错这个问题的代价，就是服务器性能的生死线


>>> 两种笨办法 #B03
在 epoll 之前，只有两种笨办法
第一种，一桌配一个服务员：每来一个连接，开一个线程盯着
一万个连接就是**一万个线程**，系统直接被拖垮
第二种，一个服务员每隔一秒扫一遍全场，挨个问有数据吗
一万个里只有一个有动静，剩下**九千多次询问全是白费力气**


>>> select 和 poll 的致命伤 #B04
后来出现了 **select** 和 **poll**，让一个线程能盯多个连接
但它们有几个致命伤
第一，select 最多只能监听**一千零二十四个连接**，直接卡死上限
第二，每次调用都要把全部连接列表，**从用户态完整拷贝进内核**
返回之后，还得从头到尾遍历一遍，才知道谁有数据
连接越多开销越大，性能随连接数直线下降


>>> epoll 的事件驱动 #B05
epoll 的思路完全反过来：**不主动问，等对方按铃**
连接进来时先注册进 epoll 的监控池，然后线程就去忙别的
数据真正到达时，**内核主动把这个连接标记为就绪**
线程只需要问一句：现在谁就绪了
没动静的连接一次都不看，这就是**事件驱动**


>>> 三个核心函数 #B06
落到代码上，epoll 就靠**三个函数**
**epoll_create**，创建一个监控池
**epoll_ctl**，往池子里添加或删除要监控的 socket
**epoll_wait**，阻塞等待，直到有连接就绪才返回
而且它只把有数据的那几个连接交给你，其余一概不提


>>> 为什么快：关键不是红黑树 #B07
很多人以为 epoll 快是因为红黑树，那只是存连接的抽屉
真正的关键是：**监控状态留在了内核里**
select 每次调用，都要把一万个连接重新拷进内核、重新扫一遍
而 epoll 只注册一次，数据到达时协议栈通过回调直接记账
epoll_wait 只是把这张账单递给你，有几个活跃连接就几项
开销只跟活跃连接数有关，跟总连接数**彻底脱钩**


>>> 你写的回调和 epoll 有啥区别 #B08
你可能想问：我平时写代码也用回调和事件驱动，有啥区别
区别不在思想，在于**事件源在谁手里**
你应用里的回调，事件是你自己造的，状态你随时能看到
但 socket 有没有数据，藏在内核的协议栈里，用户态根本看不见
想知道只有三条路：阻塞死等、轮番询问、或者让内核主动通知你
epoll 不取代你的事件循环，它只是这个循环的**事件源**


>>> LT 与 ET 两种触发模式 #B09
用 epoll 还必须懂两种触发模式，这是面试必考题
**水平触发 LT** 是默认模式：数据没读完，它就一遍一遍提醒你
安全省心，但重复通知带来额外开销
**边缘触发 ET** 是高效模式：数据来了**只通知一次**
你必须一次性把数据读完，否则剩下的部分它不再提醒
性能好但容易写错，**Nginx 和 Redis** 都默认用 ET 榨干性能


>>> Windows 和 macOS 上的同类机制 #B10
这套思想不是 Linux 独有
**macOS** 上叫 kqueue，**Windows** 上叫 IOCP
epoll 和 kqueue 是 Reactor 模式：告诉你可以读了，你自己去读
IOCP 更彻底，是 Proactor 模式：**内核读完数据才通知你**
名字和细节不同，思想一样：内核盯连接，应用只处理就绪事件


>>> Asio：站在 epoll 肩膀上 #B11
最后说说 **Asio**，它和 epoll 是什么关系
Asio 是 C++ 里用得最多的跨平台网络库，Boost 里那个就是它
你写 async_read 加回调，io_context.run 里转的就是事件循环
这个循环在 Linux 上的底层，**正是 epoll**
在 macOS 上换成 kqueue，Windows 上换成 IOCP，你的代码一行不用改
所以说，Asio 就是站在 epoll 肩膀上的**跨平台封装**


>>> 总结 #B12
最后用四句话收尾
epoll 解决的不是传输问题，而是**谁有数据**的通知问题
它快的本质：状态留在内核，开销只看活跃连接数
你写的回调和事件循环没有变，epoll 只是高效的事件源
动手写高并发服务，直接用 Asio 这类库，就自动用上了 epoll
