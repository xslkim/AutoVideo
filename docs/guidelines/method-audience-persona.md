# 受众画像先行法（受众驱动 · 写作主法）

> **一句话定位**：先写清楚「说给谁听」，再决定怎么讲。脚本的所有取舍都从一张受众画像推导，不凭作者感觉。
> **什么时候选它**：受众混杂或拿不准深浅；同一内容要出多类受众的版本；过往视频被反馈「听不懂」或「太啰嗦」。
> **用法**：本方案是三个**写作主法**之一（另两个：`method-goal-contract.md` 目标契约、`method-block-design.md` 单块设计），每次课程按症状三选一；两道**通用工序**（`process-fact-baseline.md` 事实基线、`process-av-acceptance.md` 音画验收）每次必过。脚本格式规范见同目录 `AUTHORING.md`，通用底线见同目录 `baseline.md`；本文件夹自包含，可整目录交给 LLM 使用。

---

## ① 确定目标

让脚本的所有可变决策——开场钩子、类比选择、术语深浅、高亮词、语气、跟练支持——都有一致、可解释的出处：**受众画像**。换一个画像，能系统性地产出另一个版本，而不是随机改几句。

## ② 怎样才能达成

- **画像不是人口统计学，是认知状态**。核心四件事：他已经知道什么（知识基线）、天天接触什么（日常场景）、脑子里已有的心智模型、对主题的怀疑或痛点；画像卡再加两栏：从知识基线与心智模型整理出的类比库、他不想听的内容（避雷清单），即 ③.1 的六栏。写不出核心四条的画像没有决策价值。知识基线栏写具体技术清单（「学过计网、写过 HTTP 接口」），不写「有计算机基础」这类笼统话——笼统基线会把 SSE、异步迭代器这类概念误判成「他本来就会」，前置断裂大都这么来。
- **本系列默认受众（程序员 / CS 学生）的五条共性先当公理**：能读代码、有工程概念、讨厌废话、会暂停跟练、对「魔法宣传」免疫。画像卡只记他与基线的差异；贩卖神奇、零基础铺垫、把画面已有内容再念一遍，默认进避雷清单，不必逐次论证。
- **钩子**：从他的日常场景里选他亲眼见过的现象（agent 重度用户 → 「ESC 有时停不下来」；应届生 → 「模型自己改代码，这怎么可能」）。
- **类比**：从他的知识基线里选，每个核心概念配一个他领域的类比，首次出现铺一句即收，不展开成第二堂课（应届生：SSE 粘包 ↔ 计网 TCP 字节流；业务程序员：参数校验 ↔ Controller 入参校验）。
- **术语深浅**：概念按来源三分——他本来就会：直接用；本系列前集讲过：给一句回忆钩（「上集的跨 chunk 缓冲」）带过，不重讲；本集新教：当场一句白话解释。观众可能从中间一集进来、或隔了几周才续看，不假设他记得前集细节（每集开场一句本集定位的要求见通用底线 8）。
- **高亮词**：只给他需要记住、会拿去检索或复述的词；情绪词、教学法词汇不高亮。
- **语气**：画像决定距离感（近如学长带学弟，远如评审会），全系列统一。
- **跟练与自验**：他会暂停跟练——演示命令整段可复制运行，环境与版本在首次相关处一句交代；关键结果给出可自验的预期（「你这边应该看到 7 步 9 次工具调用」），命令与数字以事实表（「事实基线」工序的产出）为准。

## ③ 具体步骤

1. **写画像卡**（≤6 行，一栏一行）：知识基线 / 日常场景 / 已有心智模型 / 对主题的怀疑或痛点 / 他能听懂的类比库 / 他不想听的内容。信息来源：任务给出的受众描述优先；没有就从已有脚本的语气、详略与术语使用推断画像；推断得出的栏目标注「假设」，随决策表一起送确认，不留空。
2. **推导决策表**：开场钩子来源、类比池（本集每个核心概念各配一个类比）、术语解释深度（概念三分：本来就会直接用 / 前集讲过给回忆钩 / 本集新教当场一句白话）、高亮词清单、语气、跟练与自验方式（命令可复制、环境前置一句、关键结果给可自验预期）。决策表必须先于写稿存在。
3. **存档**：画像卡与决策表存为脚本同目录的 `NOTES.md`，后续改稿、出变体都以此为基准。
4. **按决策表写正稿**：正稿即 AutoVideo 三件套 `meta.md` / `visuals.md` / `narration.md`（格式见同目录 `AUTHORING.md`）；概念首次出现给一句白话解释、演示给可复制的命令与可自验的预期结果，均按决策表执行。写完后过两道通用工序（事实基线、音画验收），并按文末「通用底线」过一遍。
5. **审稿用「预设问题清单」，不做自由角色扮演**：让 LLM 自由扮演读者有回音室风险——扮演者的先验与作者同源，「他没见过的词」容易被漏报。改为：从画像卡的「怀疑与痛点」栏生成一份刁钻问题清单，逐块问「这段回答了这条怀疑吗」；有真人观众时，用一次真人抽评校准决策表，之后模型审稿只做增量（只复核校准后改动过的块）。
6. **多受众变体（可选）**：技术主干与事实数字不变，换画像卡 + 决策表出新版。变体以一份已核实的事实表（「事实基线」工序的产物）为前提；若当次课程未建过，先补一张最小事实表（只列本集出现的数字、版本、行数、文件名及各自核实出处）再出变体，不要凭记忆沿用数字。

## 给 LLM 的提示词模板

> 空位（`___` 与【】）由发令方填写后使用；留空时执行方先自行盘点相关路径、列出待确认清单，再开始。

```
动笔前先读：【路径清单：已有各集脚本 / 参考文档 / 事实表（若有）：___】
受众画像卡：【知识基线：___；日常场景：___；心智模型：___；怀疑与痛点：___；类比库：___；不想听的：___】
（若画像卡留空：按上面六栏从读到的材料起草，推断得出的栏目标注「假设」。受众为程序员/CS 学生时，
五条共性直接当公理——能读代码、有工程概念、讨厌废话、会暂停跟练、对魔法宣传免疫——画像卡只填与基线的差异。）
动笔前先输出画像卡与决策表：开场钩子（从他日常场景选）、每个核心概念配一个他领域的类比、术语解释深度（概念三分：本来就会直接用 / 前集讲过给一句回忆钩 / 本集新教当场一句白话解释）、高亮词清单、语气、
跟练与自验方式（命令整段可复制、环境版本前置一句、关键结果给可自验的预期）、开场定位（每集一句：做什么、从哪个产物或 git tag 接着做）。
等我确认画像卡与决策表后，先把它们存入脚本同目录 NOTES.md，再写正稿（meta.md / visuals.md / narration.md 三件套，格式见同目录 AUTHORING.md）。
写完正稿后，从画像卡的「怀疑与痛点」栏生成一份刁钻问题清单，逐块检查「这段回答了这条怀疑吗」，列出未覆盖的块和怀疑，逐条修正或说明不覆盖的理由。
```

## 通用底线（任何方案都必须守）

> 已单文件化：见同目录 [`baseline.md`](baseline.md)，十条底线全系列共用，任何方案交稿前都必须逐条过。改底线只改 `baseline.md` 一处。

## 依据

- 内部验证：本方法经受过实战——同一集旁白曾按五版受众画像各出一版改写；程序员受众的避雷实证包括「对魔法宣传免疫」、砍掉暖场与课程运营块、把七块课程导览压进两块。
- [University of Reading 教学视频研究简报](https://research.reading.ac.uk/design-research-for-testing-diagnostics/wp-content/uploads/sites/178/2021/02/Research-Briefing_Instructional-videos_february-2021.pdf)：口语化与对话式语言的建议，支持「语气由画像推导」这条决策。
