# guidelines 方法论评审

> 审查日期：2026-08-27 · 范围：`video_res/guidelines/` 全部 5 份方法论文档
> 审查基准：仓库自身实践（`video_res/REVIEW-20260821.md`、`narration-variants/`、五课脚本、`assets/` 工具链、AutoVideo `AUTHORING.md`/`BUILD.md`）+ 外部引用逐条核实（2026-08-27 实测）
> 审查角度：文档内部一致性 · 方法论设计（含「只选一个」前提）· 引用有效性

## 总评

这是一套质量很高的方法论提炼。五份文档模板统一（定位/选择条件/①目标/②手段/③步骤/提示词模板/底线/依据），每份的 LLM 提示词模板都带「先输出中间产物、等确认再写正稿」的关口设计，与仓库「验收先行」的文化同构；尤其难得的是每套方法都锚定一个真实的仓库教训（REVIEW A1/A2→方案 3，C/D→方案 5，D1→方案 1，narration-variants→方案 2，L1-B11~B14→方案 4），不是空对空的原则汇编。外部引用 4/5 实测有效，Mayer 三原则的归属引用准确。

主要问题集中在三处：**一个框架级矛盾**（「只选一个」的前提与五套方法实际的正交性冲突）、**两处与自家实践的数字/逻辑不一致**（10–14 块 vs L1 的 19 块；时长规则自相矛盾）、以及**通用底线的五份漂移**。另有若干执行层缺口和一个支持力不足的外部引用。分级列在下。

## A. 框架与逻辑（建议必改）

### A1. 「每次只选一个方案」的前提，与五套方法的正交性矛盾

五套方法覆盖的是脚本生产**流水线的五个不同环节**，不是同一环节的五种互斥做法：

| 方案 | 环节 | 性质 |
|---|---|---|
| 01 目标契约 | 定结构 | 写作方法 |
| 02 受众画像 | 定取舍 | 写作方法 |
| 03 事实基线 | 锁数字 | **质量工序**（前置门） |
| 04 单块设计 | 写块 | 写作方法 |
| 05 音画验收 | 防翻车 | **质量工序**（后置门） |

编号顺序本身就暴露了这一点——01→05 恰是一条工作流。而现状要求「只选一个」：一个数字密集的代码库教程如果按 02 写，就没有事实表；任何方案写的稿如果不过 05 的清单，REVIEW C 项的音画穿帮照样发生。**各方案「依据」里引用的翻车案例（A1/A2/C/D），没有一个是「选错了写作方法」造成的，全是质量工序缺位造成的。**

建议重构为两层：

- **写作主法（按症状三选一）**：01 结构松散选它 / 02 受众混杂选它 / 04 看完没学会选它；
- **通用工序（任何课程必过）**：03 动笔前建事实表 + 05 交构建前过验收清单。

README 选型表相应拆成两节。这样「只选一个」对写作方法依然成立（避免给 agent 塞互相冲突的指令——这个初衷是对的），而质量门不再是可以被「没选中」绕过的可选项。

### A2. 时长规则自相矛盾，「截断」疑为「循环」笔误

01/02/03/04 底线第 5/6 条与 05 §② 均写：

> video 素材时长**必须 ≥ 块时长**（…）；**循环 >1.5 次**的素材重录或改预算。

两句话在逻辑上不能并存：素材 ≥ 块时长时视频只会**截断**（AUTHORING §3.2），永远不会循环——「循环 >1.5 次」就成了死条款。而它引用的 REVIEW C 实际执行的口径是：**循环 1.3–1.4 次可接受**（即素材短于块时长是被容忍的）。05 §② 的「（或明确接受截断）」更可能是把「循环」误写成了「截断」——截断是「≥ 块时长」的自然结果，不需要「明确接受」；需要明确接受的恰恰是短素材的循环。

建议改写成三档规则（与 REVIEW C 的实际执法一致）：

- 素材 ≥ 块时长：安全（超时自动截断）；
- 块时长 ÷ 1.5 ≤ 素材 < 块时长：可接受（循环 ≤1.5 次，重开头可见但可容忍，追求完美则补录）；
- 素材 < 块时长 ÷ 1.5：必改（重录、放慢回放、扩大区间或用 `@duration` 对齐）。

### A3. 通用底线五份漂移：自包含与单一事实来源的矛盾

实测各文档「通用底线」条数：**01 = 8 · 02 = 8 · 03 = 7 · 04 = 7 · 05 = 4**。逐条核对后确认：被删的条目都在各文档正文里有对应内容，**没有实质缺漏**；但这节自称「任何方案都必须守」，却不是一个稳定清单——跨文档 diff 全是噪音，将来改一条底线要人肉判断「这条在几份的正文里」，漂移只会越来越大。这是「本文件自包含」（单独交给 agent 时不依赖兄弟文件）与「单一事实来源」的固有代价。

自包含的意图是对的（这五份就是要被单独发给执行 agent 的），不建议改成引用共享文件。建议：

1. **冻结一份逐字一致的 8 条底线**，五份原样携带（03/04 正文已有的内容重复出现无害）；
2. 底线节首加一行「本节五份文档逐字一致，修改须五处同步」；
3. 若想加保险，`tools/` 下加一个三行的 diff 脚本，收尾时跑一次。

## B. 与仓库实践不一致

### B1. 「每集 10–14 块」被自家最好的样例打破

01 步骤 3 写「每集 10–14 块（对应 4.5–7 分钟）」。实测五课：**19 / 12 / 13 / 11 / 12**——L1 超上限 36%，而 L1 恰是 01「依据」里引为正面样板的课程，REVIEW-20260821 也给了 L1 结构合规的好评。按块均 20–25 秒推算，19 块 × ~22s ≈ 7 分钟，完全在目标时长内——说明「块数」不是好约束，「**单块时长 + 集总时长**」才是。建议改为「每集 10–20 块，单块 15–40 秒，集总长 4.5–7 分钟（字数 ÷ 4.5 + 行数 × 0.2s 估算）」。

### B2. 方案 2 的多受众变体流程隐含依赖方案 3

02 步骤 6 写「多受众变体：技术主干与事实数字不变……**不重复核对事实**」。前提是存在一份已核实的事实表——那是方案 3 的产物。若课程只选了 02（按现行规则完全合法），这句话就没有可继承的基准。建议补一句：「变体工作流以一份已核实的事实表为前提；若未建过（方案 3），先补一张最小事实表再出变体」。（若采纳 A1 的重构，此问题自动消解。）

## C. 执行层缺口（建议补充）

### C1. 方案 4 的四拍结构对非教学块过刚

「每块遵守：钩子→演示→机制→收束」对教学块成立，但每集还有片头、课程总览、小结、pi 对照、过桥块——这些块没有「演示」拍（L1-B19 小结、B18 pi 对照即如此），按模板硬写会注水。建议在 04 加豁免声明：「片头/总览/小结/对照/过桥块不强制四拍，但保留钩子与收束两拍」。

### C2. 事实表缺「数字上口」的 TTS 读法决策

旁白里的数字有个双重口径问题：同一事实，画面卡片写阿拉伯数字（`149`），旁白要念汉字（「一百四十九行」）——TTS 对阿拉伯数字、混排（`21*2`）、年份的读法不可控。03 的事实表建议加一列（或一条规约）：**上屏形式 | 上口形式**，上口形式统一汉字或走发音词典（AUTHORING §4.5），建表阶段一并冻结。L1-B18 的「七十八行 vs 149」这次能对上，靠的是人工事后核对——把它变成表列就不再依赖人的警觉。

### C3. 方案 2 的 LLM 角色扮演审稿有回音室风险

「让 LLM 扮演画像中的读者通读」——扮演者的先验来自同一模型的训练分布，倾向复述作者已有的假设，「他没见过的词」容易被漏报。两个低成本的缓解：① 不做自由扮演，改为**从画像的「怀疑与痛点」栏生成预设刁钻问题清单**，逐块问「这段回答了这条怀疑吗」；② 有真人观众时，用一次真人抽评校准决策表，之后模型审稿只做增量。

### C4. 系列级视觉语言一致性无人认领

五课脚本实际存在稳定的视觉语义（「我们」的卡片 accent 蓝、pi 对照另一套色、错误态 #f85149……），但这是脚本作者的隐性知识，五个方案都不管。换一套课程、换一个执笔 agent，这套口径就会漂移。建议在 01 的契约存档（或 05 的清单）里加一张**系列视觉语义表**：谁是什么颜色、图标、卡片语言、错误态色，系列级一次冻结，逐集引用。这与 03 的「口径唯一」是同一思想在视觉维度的投影。

### C5. 4.5 字/秒 是未经校准的系数

05 的全部时长账都建立在「旁白 ~4.5 字/秒 + 行间 200ms」上。REVIEW C 用它估出的循环次数与实况大致相符，说明量级是对的，但换音色（B00 之外）、换语速配置后未必。建议加一步：**每个音色首次使用时实测校准**（合成 3–5 行样本，实测字/秒，回填系数），预算表注明所用系数与校准日期。

### C6. 05 清单缺「构建环境预检」一项

清单全是脚本侧检查；建议加一条「构建前 `autovideo doctor` 通过（TTS / Agent 服务在线）」——把 BUILD.md §7 的前置要求接进同一张清单，避免脚本全绿、构建卡在服务不在线。

### D1. howtoegghead 引用不支持所附论点

04 把两个 egghead 链接共同挂在「先展示，再解释」与「短块、一次一个想法」下。实测 howtoegghead 该页的 "Record one thought at a time" 讲的是**录制工序**（20 秒一段便于剪辑），不是课程设计原则，与「短块」论点不是一回事。建议：删去该链接，或降格为「录制工序参考」并移出论点支撑位。

### D2. 「先演后讲」缺少一个正面框架级引用

Brame 覆盖 segmenting / signaling / modality，但**没有**「先演示后解释」的框架表述（其最接近的内容是 modality 匹配，另一回事）。「先演后讲」目前最贴切的支撑其实是 egghead 的 live demo 传统（D1 表中第一条）。两个改法：① 以 egghead 为主引用、Brame 只支撑切块与高亮；② 措辞降为经验性做法，不挂学术引用。现状把 Brame 挂在一个它没说的论点下，是全套文档里唯一一处引用与论点错位。

### D3. 方案 2 的 Reading 简报推断链略长

02 依据写「口语化、对话式语言、音画靠近等建议均指向『按受众认知状态设计』」。前两条（Mayer personalization）支持「语气」决策成立；但「音画靠近」（temporal contiguity）是关于**通道分配**的原则，与受众画像没有直接指向关系。建议把「均指向」收敛为「口语化与对话式语言的建议支持由画像推导语气」（PDF 内容未逐字核对，只针对推断链本身）。

## E. 小瑕疵（可选修复）

1. **01 步骤 5 建议契约「写进 meta.md 注释」**：meta.md 是 compile 的解析对象，块外注释的容忍度未在 AUTHORING 定义。更稳妥：独立 `plan.md` 存契约。
2. **提示词模板缺仓库上下文注入**：五个模板都是空位填空，没告诉执行 agent 先读仓库（事实表路径、已有各集、graphify 规则）。各模板首行加一句「动笔前先读【路径清单】」，与 `.cursor/rules/graphify.mdc` 的先查图规则衔接。
3. **路径风格混用**：各文档头部用绝对路径 `/home/xsl/AutoVideo/docs/AUTHORING.md`，「依据」用仓库相对路径（`docs/teaching-agent-plan.md`）。单独发给别的机器/agent 时绝对路径必失效。建议统一为「相对 my-pi-agent 仓库根」并在头部声明一次基准。
4. **编号暗示顺序但未说明**：01–05 的编号恰是流水线顺序（这是 A1 论据之一），却宣称「相互独立、只选一个」。加一句「编号即流水线位置，非优先级」既诚实又给 A1 的重构铺路。
5. **04 块卡行数预算（3–8 行）与四拍最小行数（4 行）轻微不齐**：钩子 1 + 演示 1 + 机制 1 + 收束 1 = 4 行起，预算下限 3 行永远用不满。改「4–8 行」即可。

## 已核对无误的项（放心的清单）

- **模板一致性**：五份的章节骨架、①②③结构、「用法」声明逐份对齐，无缺节。
- **关口设计**：五个 LLM 模板全部要求「先输出契约/决策表/事实表/块卡/验收表，等确认后再写正稿」——无一例外。
- **教训锚定**：每个方案的「依据」都能在仓库内找到对应事件，且事件与方案的因果成立（A1/A2→03、C/D→05、D1→01、D2→05、narration-variants→02、B11–B14→04）。
- **Mayer 归属准确**：04 对 segmenting / signaling / coherence 三原则的转述与 DLI、Brame 原文一致（2026-08-27 核对）。
- **底线内容无实质缺漏**：03/04/05 底线删掉的条目均在各自正文有覆盖（A3 指出的是结构性漂移，不是内容空洞）。
- **链接存活**：5 个外部链接全部可达（4 个内容核对通过，1 个 PDF 仅确认存在）。
- **Brame 引用年份正确**（2016）。
