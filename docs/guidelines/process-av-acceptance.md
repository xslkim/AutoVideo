# 音画预算与验收回路法（落地驱动 · 通用工序）

> **一句话定位**：把「验收先行」用到脚本生产本身。脚本交给构建之前，先算账、先选模式、先过验收清单——它必须是可构建、节奏对、口径稳的成品。
> **什么时候用它**：**每次课程必过**——它是交构建前的质量门，防构建翻车（音画穿帮等）。
> **用法**：本方案是**通用工序**，不参与写作主法的「三选一」（三份主法 `method-goal-contract.md` / `method-audience-persona.md` / `method-block-design.md` 中按症状选一份）。脚本格式规范见同目录 `AUTHORING.md`，通用底线见同目录 `baseline.md`；本文件夹自包含，可整目录交给 LLM 使用。

---

## ① 确定目标

脚本在交付构建**之前**通过一份逐项可判对错的验收清单：视觉模式全部选对、音画时长全部匹配、系列口径一致、演示可按原顺序复现。构建后只剩抽查，不再返工。

## ② 怎样才能达成

- **时长先算账**：按「字数 ÷ 校准字/秒 + 行数 × 0.2s」估算块时长（字数按去掉 `**` 高亮符的旁白纯文本计，行数按非空旁白行计，0.2s 即 AUTHORING §4.1 的行间 200ms 静音），先有时长预算，再决定视觉。时长系数必须按音色实测校准（见步骤 1）——~4.5 字/秒只是 B00 音色的量级参考，换音色、换语速配置后未必成立。
- **音画时长三档规则**：
  - 素材 ≥ 块时长：**安全**，超时自动截断（AUTHORING §3.2）；
  - 块时长 ÷ 1.5 ≤ 素材 < 块时长：**可接受**（循环 ≤1.5 次；追求完美则补录）；
  - 素材 < 块时长 ÷ 1.5：**必改**（重录、放慢回放、扩大录制区间或用 `@duration` 对齐；18s 旁白配 3.4s 素材、循环 5.4 次的 pi-scroll 穿帮事故就在这一档）。
- **视觉模式按 AUTHORING §3.0 优先级**：
  - 静态能表达（精确文字/代码/数据）→ `html`；
  - 必须跟随旁白推进的动效（逐条高亮、流程推进）→ `animation`，且描述中声明用 `props.lineTimings` 驱动、禁绝对时间戳（TTS 时长每次会变，硬编码时间戳会静默错位）；
  - 真实运行画面 → `video(./path)` 实录，并在 `<!-- -->` 注释里记录录制命令。
  - 留白多的画面（单一标题、简单对比）不要给 `animation`——coverage 质量门会反复重试甚至失败。
- **口径一致性也是验收项**：视频实际时长与旁白里的「课时」说法不能矛盾（真实事故：标注仅 4.5–7 分钟的视频里念「接下来的四十分钟」）。

## ③ 具体步骤

1. **校准系数，做时长预算表**：音色以 meta.md 的 `voiceRef` 为准。每个音色首次使用时，先用管线的 tts 阶段合成 3–5 行代表性样本（`autovideo tts --block` 可按块单独合成，见 AutoVideo `docs/BUILD.md`），`ffprobe` 量出样本音频总时长，按「系数 = 样本总字数 ÷（音频总时长 − 样本行数 × 0.2s）」回填——与估算公式同口径，剔除行间静音。再逐块算估算时长（字数 ÷ 系数 + 行数 × 0.2s），累加成集时长（硬约束 4.5–7 分钟）。预算表注明所用系数与校准日期，存进项目目录随脚本走——它就是验收模板路径清单里的「时长系数校准记录」。超预算先砍块、不砍字：整块删掉与单集目标关联最弱的块，而不是逐句压缩旁白字数（逐句压字伤节奏、易致口径漂移）。
2. **逐块选视觉模式**：按上面优先级决策；video 块的素材时长用 `ffprobe` 实测（或素材目录自带的时长记录），按三档规则核对并记入预算表；落在必改档又没条件重录时，用其余三招兜底。
3. **过预构建验收清单**：
   - 结构：两文件块 ID 一一对应；指令只写在 visuals.md；`slug` 全小写显式声明
   - 字幕：全量扫描无超 50 字的行（计数规则见 AUTHORING §4.4：中文 1 字 1 计数、标点也算）；中文旁白无英文短语
   - 可读性：上屏文字与代码的字号不低于 AUTHORING §3.1 最低字号表（1080p：正文 ≥28px、代码块 ≥24px）——观众会暂停读屏照敲，字小即硬伤
   - 事实：所有数字有出处且全系列口径唯一（含数字的上屏/上口形式已冻结）
   - 敏感信息：全量扫描无明文 token、无内网地址、无真实用户名（教训：素材示例残留过明文 token、画面 HTML 暴露过真实用户名）
   - 音画：animation 块声明 lineTimings、跟随旁白的推进不用绝对时间戳（入场编排的 `[Xs]` 节拍允许）；video 素材全部落在三档规则的前两档；画面背景填满全屏、避让底部字幕区（1080p 为 120px，其他分辨率按 高×120/1080 换算，AUTHORING §3.1）
   - 叙事：每集开头独立可入——开场块交代本集做什么、从哪个产物或 git tag 接着做，不假设观众记得上集细节（观众可能从中间一集进场）；每集结尾有下一集钩子（系列末集无下一集时，以全系列收束或延伸阅读指引替代，不判不通过）；系列口径（术语、称呼、进度说法）一致；可懂性五查：① 对照契约里的术语首现表逐行回查——每个术语/专名要么在契约既有知识清单内，要么旁白里有交代句，清单查无即不通过；② 指代闭合：每个指示词/定指的前件在旁白纯文本中可指认、且先于指代出现，画面文字不算前件；③ 设问/承接的前件在同句或同块内——判定法：抽掉前文，该句仍自足；④ 主语可辨：课程承诺、观众操作、客观事实三种陈述的主语不混；⑤ 跨抽象层引用（如从应用层跳到传输层）有显式层级桥，既有知识不能豁免此条；凡出现演示或运行结果的块，须有一句机制或原因解释，不得只见证不解释
   - 视觉语义：本集画面符合系列视觉语义表（各方的颜色/图标/卡片语言/错误态色一致）；语义表缺失时，先从已交付各集归纳一张落盘再对照；系列首集无表可归纳时，本集先定义一张（存系列公共位置或本集目录），后续集对照
   - 跟练：本集演示的命令与代码按展示顺序在真实环境完整跑通过一遍（`process-fact-baseline.md` 核单个事实，这里核整条演示链路）；演示起点状态（上一集产物或 git tag）已在脚本或 NOTES.md 标明，观众能从同一起点复现；纯概念讲解、无演示可跑的集跳过本项
   - 环境：构建前 `autovideo doctor` 通过（TTS / Agent 服务在线）
   - 纯音频通读（可懂性五查的执行方式）：验收 agent 只读 narration.md 的旁白纯文本——剔除 `>>>` 块标题行、不参照 plan.md / facts.md / visuals.md，审稿人知道的不能比观众多——模拟线性音频流逐行通读，凡指代或前提在这份纯文本里闭不合的，判不通过
4. **构建后验收成片**（构建由构建 agent 按 BUILD.md 执行；拿到 MP4 后按下面四项逐项过，不再只是随机抽查——EP02–07 验收即按此执行）：
   - **兜底块逐块抽帧**：构建日志里凡出现 `assembly failed … falling back to free generation` 的块，逐块从 `output/partials/<Bxx>.mp4` 中段抽帧（`ffmpeg -ss <块时长/2> -frames:v 1`），对照 visuals.md 的块描述核对内容、高亮跟随与字幕避让——自由生成的组件没有组装件的样式保证，必须全检。
   - **QA 警告逐条定位**：render 阶段的 QA 警告（如字幕安全区）带时间戳；按 `output/partials/` 各块 `ffprobe` 时长累计定位到块，抽帧确认是否真重叠。确属误报（内容在字幕区上方结束）的，记录原因接受；真重叠的回到 visuals 修该块。
   - **html 块全检**：逐块核对 `public/html-shots/<Bxx>.png`——表格列对齐、行内引用（file:line）与事实表一致、无溢出裁切。
   - **时长与音画对位**：`ffprobe` 实测成片总时长，与步骤 1 预算表比对（估算口径与实测偏差超 ±15% 时在预算表回写校准系数）；随机抽 3 块抽帧看字幕换行与音画对位。有问题回到对应工序修，不留到下一集。
5. **清单回写**：本次发现的每个新问题，作为项目专属条目追加进步骤 3 的清单（维护本系列自己的清单副本，不改本文档），下次验收直接可用。

## 给 LLM 的提示词模板

> 空位（`___` 与【】）由发令方填写后使用；留空时执行方先自行盘点相关路径、列出待确认清单，再开始。

```
验收前先读：【路径清单：脚本 / 事实表 / 素材目录 / 时长系数校准记录 / 系列视觉语义表：___】。脚本已完成，现在做预构建验收，逐块输出一张表：
块 ID | 旁白字数（去 `**` 高亮符）→估算时长（系数 __ 字/秒，校准日期 __）| 视觉模式及理由 | 素材时长落在三档规则的哪一档（非 video 块填 —）| 字幕是否 ≤50 字、画面字号是否达到 AUTHORING §3.1 下限 | 是否有英文短语 | 数字是否都有出处。
逐块表之外，再按上面步骤 3 的整集级条目（结构对应、slug、单集入口与叙事钩子、系列口径、可懂性五查与纯音频通读、视觉语义表、跟练复现、敏感信息、音画合规、autovideo doctor）逐项列 通过/不通过。
若路径清单里没有时长系数校准记录，先按上面步骤 1 实测校准再填表。
最后列出所有不达标项，先不要改，等我确认后再逐项修。
```

## 通用底线（任何方案都必须守）

> 已单文件化：见同目录 [`baseline.md`](baseline.md)，十条底线全系列共用，任何方案交稿前都必须逐条过。改底线只改 `baseline.md` 一处。

## 依据

- 内部：同目录 `AUTHORING.md` §3.0（模式选择优先级与 coverage 质量门）、§3.1（lineTimings 规则、最低字号表、字幕安全区）、§4.4（字幕上限）、AutoVideo `docs/BUILD.md`（构建前置要求、`tts --block` 按块合成）——验收清单的条目来源。
- 方法论来源：「验收先行」原是本课程开发中的完成标准——每课目标产物必须能跑、真实环境手工验证一次；本工序把它前置到脚本交付构建之前。
- 内部样板：已有各集的开场块即交代本集目标、不依赖观众记得上集——「单集入口独立」验收项的正面样板（仅覆盖「本集定位」半句，「从哪个产物或 git tag 接着做」的锚点需在写作时补上）。
