# 三层目标契约法（结构驱动 · 写作主法）

> **一句话定位**：先签合同，再动笔。系列、单集、块三层各立一句可验收的目标，自顶向下分解，反向追问对齐。
> **什么时候选它**：一套全新系列从零起步；或出现过结构松散、内容膨胀、块与主题脱节的问题。
> **用法**：本方案是三个**写作主法**之一（另两个：`method-audience-persona.md` 受众画像、`method-block-design.md` 单块设计），每次课程按症状三选一；两道**通用工序**（`process-fact-baseline.md` 事实基线、`process-av-acceptance.md` 音画验收）每次必过。脚本格式规范见同目录 `AUTHORING.md`，通用底线见同目录 `baseline.md`；本文件夹自包含，可整目录交给 LLM 使用。

---

## ① 确定目标

系列、单集、块三层各有一句**可验收的目标**，且严格对齐：块目标的合集 = 单集目标，单集目标的合集 = 系列目标。任何一层说不出「看完能干什么」，就还没资格动笔。

| 层 | 目标要回答的问题 | 示例（某五课系列教程） |
|---|---|---|
| 系列 | 观众看完全部，**能做出/说出什么**？ | 能从零写出一个 1100 行的 coding agent，并讲清每一层为什么 |
| 单集 | 这一集交付哪一级**能力台阶**（从哪出发、到哪结束）？ | 第 1 课：让模型说话——手写 SSE 客户端，终端逐字看到回答 |
| 块 | 这一块观众**带走哪一句话**？ | 「HTTP 响应是字节流——TCP 不保证事件边界，天真解析器必丢字」 |

## ② 怎样才能达成

- **目标写成可观察行为**：禁止「介绍」「讲解」「了解」「掌握」「精通」这类无法验收的动词；目标动词用工程动词：手写、跑通、定位、说出为什么。
- **先定终点，再拆台阶**：系列目标 = 终点能力；单集目标 = 能力递进的一级台阶；块目标 = 一个且仅一个要点。顺序依赖必须成立：第 N 集用到的概念，必须在前 N-1 集讲过，或属于受众既有知识；前集概念在本集首次出现时给一句回指（如「上一集的手写解析器」），不裸用、不重讲。同一集内同理：本集首现的概念，要么前块已讲、要么本块先用一句话搭桥再下断言；块内任何设问/断言，其前提与依据须先于它出现——前提还没交代，就先写一句动机陈述；依据放在断言之前，不倒置。
- **目标里写明不做什么**（范围护栏）：如「不 import 现成框架、零依赖」「全系列累计 ≤1400 行」——范围护栏要具体到可检查。

## ③ 具体步骤

1. **写系列目标契约**（≤5 行）：受众一句话（含默认他会什么，如「写过 TypeScript、日常用命令行」）/ 看完获得的能力一句话 / 明确不讲的范围 / 跟练前置（环境基线一句话，如「Node ≥ 23.6、零依赖」）/ 每集交付物（能跑的产物 + git tag + 一条可执行的验证方式如 `node --test`；tag 是观众暂停跟练时对齐环境的锚点）。
2. **画单集递进图**：每集一句话目标 + 一行「为什么排在上一集之后」+ 入口状态（从哪个 tag 出发、本集假设的既有知识）。检查概念依赖链是否成立；不成立就调集序、补一集前置，或把该概念显式声明为「受众既有知识」并不再展开。入口状态供中途入场的观众（常从搜索直达中间一集）判断要不要回补前置、checkout 哪个 tag 对齐环境。
3. **列块清单**：每块一行「本块要点」，并标注它支撑哪条单集目标。**块数不是硬约束，时长才是**（本课程第 1 课 19 块仍被评审认可）：每集 10–20 块、单块 15–40 秒是参考区间，集总长 4.5–7 分钟是硬约束。时长估算公式与 4.5 字/秒兜底系数见文末「通用底线」第 6 条（系数校准见「音画验收」工序）；契约阶段还没有旁白全文，按行数预算粗估（如每块 4–8 行 × 约 20 字/行）。估算落出区间就调结构：总长超上限砍块或拆集、不足下限并块或补块；单块超 40 秒拆、不足 15 秒并。
4. **对齐检查**（反向追问）：任意挑一块，能说出它支撑哪条单集目标；任意挑一条单集目标，能指出由哪几块支撑；对不上的块删掉。再逐集问「删掉它，系列目标是否仍成立」——成立说明它是脂肪，砍。再为本集建**术语首现表**：逐块列出旁白将用到的术语/专名，逐个标注来源——契约既有知识清单 / 前集（须回指）/ 本集前块 / 本块搭桥——四者皆无即不通过（回契约补登记，或改写法）；表存各集目录（`term-table.md`，与契约 plan.md 并列维护），交构建前由验收工序对照旁白逐行回查。
5. **契约存档**：三层目标写进独立的 `plan.md`，全系列只存一份（系列公共位置或首集的项目目录：AutoVideo 侧即 `project/<项目名>/plan.md`），各集引用同一份；**不要**写进 meta.md 注释（meta.md 是编译解析对象，AUTHORING 只定义了视觉描述里的 `<!-- -->` 注释，meta.md 中注释容忍度未定义）。同一份契约里冻结**系列视觉语义表**：叙事各方的卡片颜色（如「我们」一方 accent 蓝）、图标、卡片语言（卡片文案的中/英文口径）、错误态色（如 `#f85149`），系列级一次冻结、逐集引用。
6. **按契约写正稿**：每块围绕它的一句话要点展开（旁白用观众语言，不照搬契约措辞）；写完后过两道通用工序（事实基线、音画验收）和文末「通用底线」。

## 给 LLM 的提示词模板

> 空位（`___` 与【】）由发令方填写后使用；留空时执行方先自行盘点相关路径、列出待确认清单，再开始。路径清单可填已有各集脚本（如 `lesson*/`）、事实表（「事实基线」工序的产出，若无则先按其补一张）；受众如「有计算机基础的程序员和 CS 学生」。

```
动笔前先读：【路径清单：已有各集脚本 / 参考文档 / 事实表（若有）：___】。
我们要做一套《___》系列技术教程，受众是 ___。
请先不要写脚本。先输出三层目标契约：
1. 系列目标：观众看完全部能 ___（可观察行为）；明确不讲 ___；
   跟练前置（环境基线）___；每集交付物 = 能跑的产物 + git tag + 一条可执行的验证方式；
2. 单集递进：分 ___ 集，每集一句话目标 + 一行为何排在上一集之后
   + 入口状态（从哪个 tag 出发、本集假设的既有知识）；
3. 每集块清单：每块一句话要点 + 支撑的单集目标；
   每集 10–20 块、单块 15–40 秒为参考，集总长 4.5–7 分钟为硬约束；
4. 系列视觉语义表：叙事各方的卡片颜色、图标、卡片语言、错误态色（系列级冻结）。
等我确认契约后，先把契约存入项目目录 plan.md，再逐集展开成 meta.md / visuals.md / narration.md。
写正稿时：每块只服务它自己的一句话要点。契约要点是作者向工作语言，不是旁白候选句；让观众听懂要点所需的前提交代（首现术语一句白话、设问或断言的前件、一句动机）属于服务要点本身，不算无关内容；与要点及其可懂性都无关的内容一律不写。（反例：「先说环境基线，只有三条。」——复读块标题、工作术语无交代；正例：「动手之前，你的机器要满足三个条件。」）
```
