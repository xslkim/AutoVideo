# 单块单点 · 先演后讲法（教学法驱动 · 写作主法）

> **一句话定位**：每块只教一件事，观众先看到现象/演示，再听到解释。
> **什么时候选它**：系列结构已定，主要问题是「看完没学会」——节奏平、概念挤、先讲定义劝退观众。
> **用法**：本方案是三个**写作主法**之一（另两个：`method-goal-contract.md` 目标契约、`method-audience-persona.md` 受众画像），每次课程按症状三选一；两道**通用工序**（`process-fact-baseline.md` 事实基线、`process-av-acceptance.md` 音画验收）每次必过。脚本格式规范见同目录 `AUTHORING.md`，通用底线见同目录 `baseline.md`；本文件夹自包含，可整目录交给 LLM 使用。

---

## ① 确定目标

每个块只教一件事；观众在听到解释**之前**先看到现象或演示；任何时候观众需要同时记住的新概念不超过一个。

## ② 怎样才能达成

- **块内固定四拍**：**钩子（现象/问题）→ 演示（真实运行/对比）→ 机制（为什么会这样）→ 收束（一句话带走，必要时过桥到下一块；带演示的块优先落成观众可自验的一点——预期输出或判断标准，不写空泛总结）**。本课程第 1 课的 B11–B14 是正面样板：先让天真解析器吐出乱码（演示），再讲跨 chunk 缓冲的修法（机制）——「先看见坏，再修」。
- **四拍是教学块的默认，不是全部块的枷锁**：片头、课程总览、小结、pi 对照（与工业级参照实现 pi 对比的块）、过桥块没有「演示」拍，不强制四拍，但保留钩子与收束两拍；这五类之外的块都是教学块。
- **演示用真材实料**：观众能读代码、会暂停跟练——演示拍优先真实代码与真实运行，不用玩具示例充数；演示里出现的命令和代码必须能从本集交付物原样复现。
- **一块一个新概念**：概念首次出现，当块用一句白话解释，不展开；第二次出现直接用；两个新概念都绕不开时，拆成两块。
- **跨集引用给回指**：观众可能从中间一集进来——前集已讲的概念在本集首次出现时，给一句回指（「上一集的手写解析器」）后当既有知识用，不重讲也不裸用。
- **coherence（克制）**：块内只留支撑本块要点的话。暖场、课程运营信息（教学法、标签规则）能压进一句就压进一句，压不进就删。
- **高亮词只给「要记的词」**——机制名、协议字段、关键数字；情绪词（「黑盒」「兴奋」）不高亮。

## ③ 具体步骤

1. **写块卡**（先于旁白，每块一张卡）：本块一句话要点 / 观众先看到什么（演示或现象）/ 行数预算（4–8 行；按通用底线第 6 条公式估算块时长，单块预算 15–40 秒，冲突时以时长为准——超 40 秒减行或拆块、不足 15 秒并入相邻块；字/秒系数校准见「音画验收」工序）/ 高亮词（≤2 个）。块卡全部确认后再展开。
2. **按四拍写旁白**：钩子 1 行 → 演示 1–3 行 → 机制 1–3 行 → 收束 1 行；非教学块（片头/总览/小结/对照/过桥）写：钩子 1 行 → 内容 2–6 行 → 收束 1 行。超 30 字的行按标点拆开。
3. **逐块自检四问**：① 解释之前有没有先给现象？② 本块新概念是否只有一个？③ 新概念有没有一句白话解释（前集概念有没有一句回指）？④ 逐行问：这行删掉会损害要点吗（不会就删）？非教学块①–③不适用，只查④。
4. **对照反模式清单**：
   - 演示跑了、机制没讲（只见证不解释＝魔法宣传）
   - 演示依赖未声明的环境或前置状态（跟练复现不了，信任一次清零）
   - 用绝对时间戳假设旁白节奏（TTS 时长每次会变，必须用 `props.lineTimings` 驱动）
5. **整集过一遍节奏，收尾过工序**：相邻块的要点密度均匀，重概念块之间用演示块缓冲；每集结尾一块做收束 + 下一集钩子；正稿完成后过两道通用工序（事实基线、音画验收），并按文末「通用底线」过一遍。

## 给 LLM 的提示词模板

> 空位（`___` 与【】）由发令方填写后使用；留空时执行方先自行盘点相关路径、列出待确认清单，再开始。「块清单」是上游结构方案（`method-goal-contract.md` 第 3 步「列块清单」或等价产出）：每块一句要点 + 支撑的单集目标、有先后顺序；没有块清单时先按其补齐，再进本方案。

```
动笔前先读：【路径清单：本集块清单 / 已有各集脚本 / 参考文档 / 事实表（若有，「事实基线」工序产出）：___】。
按块清单逐块写旁白。教学块遵守：四拍结构（钩子→演示→机制→收束，收束优先给可自验的预期输出或判断标准）、
一个新概念、新概念当块一句白话解释、前集概念首次出现给一句回指、
演示可从本集交付物原样复现、机制必讲（不只演示成功）、
每行一句、推荐 15–25 字（超 30 字按标点拆开，硬上限 50 字）、
高亮词每块 ≤2 个且每行至多 1 处（只给术语和数字）；
片头/总览/小结/对照/过桥块不强制四拍，写「钩子 1 行 + 内容 2–6 行 + 收束 1 行」。
先输出全部块卡（要点/演示内容/行数预算 4–8 行/高亮词），等我确认后再展开；
展开时同时产出 visuals.md 与 narration.md，两文件块 ID 一一对应，visuals.md 的视觉描述按块卡「演示内容」写。
展开后逐块做自检四问（非教学块只查第④问），列出不达标的块并给修改版。
```

## 依据

- 「先展示，再解释」来自技术录屏课的经验传统：[egghead · Show First, then Maybe Explain](https://egghead.io/lessons/tools-show-first-then-maybe-explain)。
- 切块、高亮、克制（segmenting / signaling / coherence）的证据基础：[Mayer 多媒体学习原则综述（Digital Learning Institute）](https://www.digitallearninginstitute.com/blog/mayers-principles-multimedia-learning)、Brame (2016) [Effective Educational Videos](https://doi.org/10.1187/cbe.16-03-0125)。
