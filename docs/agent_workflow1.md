# Ubuntu系统 剧本到口播教学视频全自动化Agent工作流搭建与执行规范文档
## 文档说明
本文档面向无人工干预的自动化Agent，规范了在**Ubuntu 22.04 LTS x86_64**系统（含WSL2 Ubuntu 22.04 LTS镜像）下，从Markdown格式教学剧本到完整口播教学视频的全流程自动化执行标准。核心覆盖环境搭建、资料检索、工具使用、流程执行、错误排查与重试全环节，全程无需人工介入，Agent需严格遵循本规范完成所有操作。

### 适用范围
- 系统环境：Ubuntu 22.04 LTS x86_64 桌面版/服务器版、WSL2 1.2.0+ 配套Ubuntu 22.04 LTS镜像
- 输入源：结构化Markdown教学剧本、配套项目git源码仓库
- 输出成果：符合剧本要求的完整教学视频、全流程源文件、执行报告
- 核心约束：所有操作必须可复现、可追溯、合规安全，无人工干预即可闭环执行

## 一、整体工作流架构与Agent核心职责
### 1.1 全流程核心阶段
Agent需按以下时序完成全流程执行，前一阶段校验通过后方可进入下一阶段，禁止跨阶段无序执行，支持断点续跑：
1.  剧本解析与需求拆解阶段
2.  运行环境搭建与依赖校验阶段
3.  口播音频自动化生成阶段
4.  视频素材自动化生成阶段
5.  视频合成与导出阶段
6.  结果校验与交付归档阶段

### 1.2 Agent核心职责
- 自主完成全流程环境搭建、工具选型与配置，保证环境稳定可用
- 按规范完成权威资料检索，所有操作必须有官方/权威来源支撑
- 按剧本要求完成全流程任务执行，保证输出内容100%匹配剧本需求
- 全流程错误自动排查、修复与重试，记录完整执行日志，无法修复时执行降级方案
- 完成最终成果校验、归档与交付报告生成
- 严格控制系统资源占用，避免主机卡死、系统不可逆损坏

## 二、Agent资料检索核心规范
本章节为Agent执行所有操作的前置准则，所有环境搭建、工具使用、错误修复的操作，必须先完成对应资料检索，禁止无依据的盲目操作。

### 2.1 资料检索优先级原则
Agent必须按以下优先级从高到低选择资料来源，禁止使用低优先级来源覆盖高优先级来源的规范：
1.  **第一优先级（权威唯一标准）**
    - Ubuntu官方文档（仅适配22.04 LTS版本）
    - 所用工具的官方文档、官方GitHub仓库README、Wiki、官方维护的常见问题页面
    - 所用AI工具/API的官方开发者文档、错误码说明文档
2.  **第二优先级（可靠补充来源）**
    - 工具官方GitHub仓库的Issues区（近3年内、高赞、官方维护人员回复的解决方案）
    - Ask Ubuntu、Stack Overflow平台近3年内、点赞数≥100的适配Ubuntu 22.04 LTS的解决方案
    - 国内权威开源镜像站（阿里云、清华大学开源软件镜像站）官方发布的源配置与工具安装文档
3.  **第三优先级（有限参考来源）**
    - 权威技术社区（InfoQ、Linux中国、掘金）的原创技术教程，必须明确标注适配Ubuntu 22.04 LTS，且有完整的执行步骤与验证方法
4.  **禁止使用的来源**
    - 个人博客无验证的零散教程、低质复制粘贴的非原创内容
    - 发布时间超过3年且无更新的过时教程
    - 适配其他Linux发行版（CentOS、Debian等）、Windows/macOS系统的教程
    - 非官方的第三方PPA源、一键安装脚本、修改系统核心配置的非官方方案

### 2.2 资料检索方法规范
1.  **精准检索规则**
    所有检索必须带上核心限定词「Ubuntu 22.04 LTS」+ 工具名 + 具体操作/错误核心信息，禁止模糊检索。例如：检索「Ubuntu 22.04 LTS Remotion 无头渲染 环境依赖」，而非「Remotion 安装」。
2.  **版本匹配规则**
    所有工具的安装与使用，必须先检索该工具在Ubuntu 22.04 LTS下的兼容稳定版，优先使用LTS/正式稳定版，禁止使用alpha、beta等测试版，除非官方明确推荐用于生产环境。
3.  **错误定位检索规则**
    遇到执行错误时，必须先提取错误的核心关键词（报错代码、异常描述、依赖包名、操作场景），加上「Ubuntu 22.04 LTS」进行精准检索，优先查找官方给出的解决方案，禁止无定位的盲目重试。
4.  **依赖冲突检索规则**
    遇到依赖冲突时，先检索对应工具的官方依赖要求，再匹配Ubuntu 22.04 LTS系统预装的依赖版本，找到官方认可的兼容版本组合，禁止强制覆盖系统核心依赖（libc、glibc等），避免系统不可逆损坏。
5.  **多方案冲突决策规则**
    当多个高优先级来源的方案不一致时，优先选择「官方最新发布、适配Ubuntu 22.04 LTS、不修改系统核心配置、风险最低」的方案，禁止擅自选择高风险操作。

### 2.3 资料使用规则
- 所有操作步骤必须完全遵循检索到的权威来源，不得擅自修改核心步骤、参数
- 若不同优先级来源的规范存在冲突，必须以高优先级来源为准
- 所有检索到的资料来源、核心内容必须记录到执行日志中，保证所有操作可追溯
- 若本文档未覆盖的场景，必须先完成权威资料检索，记录方案来源与风险点后，方可执行操作

## 三、环境搭建全流程执行规范
本章节为Agent搭建运行环境的唯一执行标准，必须按步骤顺序执行，前一步校验通过后方可进入下一步。

### 3.1 基础环境前置要求
Agent执行环境搭建前，必须先完成基础环境校验，符合以下要求方可继续：
- 系统版本：Ubuntu 22.04 LTS x86_64 或 WSL2 1.2.0+ 配套Ubuntu 22.04 LTS镜像
- 硬件配置：最低2核8G内存，50G以上可用磁盘空间；GPU渲染需NVIDIA显卡+Ubuntu官方闭源驱动
- 网络要求：可正常访问外网，包括GitHub、Ubuntu官方源、所用工具的官方地址、AI API接口地址
- 权限要求：拥有sudo权限，可执行系统级包管理操作，同时具备普通用户目录的读写权限
- WSL2额外要求：已开启Windows系统挂载，C盘对应挂载路径为`/mnt/c/`，具备读写权限

### 3.2 系统环境初始化与基础依赖安装
#### 3.2.1 执行目标
更新系统软件源，安装系统级基础依赖，搭建稳定的系统运行底座，保证后续工具安装的基础环境正常。

#### 3.2.2 操作规范
1.  软件源配置与更新
    - 优先使用Ubuntu官方软件源，执行系统源更新与升级操作
    - 若官方源访问速度异常，可检索清华大学/阿里云开源镜像站的Ubuntu 22.04 LTS官方源配置文档，按官方步骤更换镜像源，禁止使用非官方的源配置
    - 源更新完成后，必须执行系统已安装包的升级操作，保证系统依赖处于最新稳定版
    - 不可逆操作前置要求：修改系统源前，必须先备份原源配置文件，失败后可一键回滚
2.  系统级基础依赖安装
    - 所有依赖必须通过apt包管理器安装，禁止手动编译安装系统核心依赖
    - 必须安装的基础依赖包括：编译工具链build-essential、git、curl、wget、FFmpeg、Python3、Python3-pip、Python3-venv、Chromium无头浏览器全套依赖、音视频处理基础依赖
    - Node.js安装规范：优先通过NodeSource官方维护的PPA源安装Node.js 20.x LTS版本（适配Remotion最低版本要求），禁止使用Ubuntu官方源的低版本Node.js
    - 安装过程中，必须保留完整的安装日志，记录每个依赖的安装版本与状态
3.  权限与目录配置
    - 在普通用户目录下创建工作目录，所有项目文件、工具、素材均存放于该目录，禁止在系统根目录、系统级目录存放用户数据
    - 配置合理的目录读写权限，禁止使用777等过度开放的权限配置
    - 所有API密钥、访问凭证必须通过环境变量配置，禁止硬编码到文件中，禁止提交到git仓库
    - Python虚拟环境规范：必须在工作目录下通过Python3 venv创建独立虚拟环境，所有Python相关操作必须先激活该虚拟环境，禁止使用系统全局Python环境执行任何pip安装、脚本运行操作
    - WSL2路径规范：Windows路径需自动转换为WSL2挂载路径，例如`C:\d\AutoVideo\docs`对应`/mnt/c/d/AutoVideo/docs`，执行操作前必须先确认目录存在，不存在则递归创建

#### 3.2.3 校验标准
- 软件源更新与升级无报错，执行apt check命令无依赖损坏提示
- 每个基础依赖安装完成后，必须执行版本校验命令，确认命令可正常执行，版本符合兼容要求
- 工作目录创建完成，读写权限正常，环境变量配置生效，Python虚拟环境可正常激活
- WSL2环境可正常访问Windows挂载路径，读写无异常

#### 3.2.4 错误处理与重试规则
1.  软件源更新失败：先检查网络连通性，再更换官方推荐的镜像源，每次更换不同的权威镜像源，最多重试3次
2.  依赖安装失败：先执行apt --fix-broken install修复依赖损坏，再提取报错核心信息，精准检索解决方案，最多重试3次；若仍失败，查找该依赖的官方替代安装方案，禁止使用--force-yes等强制安装参数
3.  权限配置失败：检查用户组与目录权限配置，按官方文档修正后重试，最多重试3次
4.  WSL2路径访问失败：检查Windows挂载权限，重新挂载对应磁盘，修正路径格式后重试，最多重试3次

### 3.3 核心工具链安装与配置
Agent必须按「先选型校验，后安装配置，完成后功能校验」的流程执行，所有工具选型必须符合「开源免费、官方支持Ubuntu系统、有完善的自动化API、个人/小团队免费商用授权清晰、社区活跃」的原则。

#### 3.3.1 剧本解析与自动化调度工具
1.  工具选型：Python3 + 官方维护的Markdown解析、数据校验、任务调度相关依赖
2.  安装配置规范：
    - 所有Python依赖均安装在项目独立虚拟环境中，禁止安装到系统全局Python环境
    - 所有依赖包必须从PyPI官方源安装，优先使用官方维护的稳定版，指定版本号安装，禁止使用无维护的第三方包
3.  校验标准：虚拟环境可正常激活与退出，pip安装命令无报错，相关模块可正常导入，无依赖缺失提示
4.  错误处理：虚拟环境创建失败，先检查Python3-venv包是否正常安装，修复后重试最多3次；依赖安装失败，检索兼容Ubuntu系统的版本，指定版本号安装，最多重试3次

#### 3.3.2 口播音频生成工具
1.  工具选型：优先选择有官方Ubuntu适配、完善API、支持中文语音合成、个人/小团队免费商用授权清晰的工具，分为两类备选：
    - API类工具：官方提供Ubuntu适配SDK的语音合成API
    - 开源本地工具：官方支持Ubuntu系统部署的开源语音合成模型
2.  安装配置规范：
    - API类工具：按官方文档安装对应SDK，通过环境变量配置API密钥，执行测试调用，确认接口可正常访问
    - 开源本地工具：按官方GitHub仓库的Ubuntu安装文档执行，优先使用官方提供的一键安装脚本，禁止擅自修改核心代码
3.  校验标准：可正常生成10秒以内的测试音频，音频可正常播放，语音清晰，内容与输入文本一致，无报错
4.  错误处理：
    - API调用失败：先检查网络与密钥配置，再检索官方错误码文档定位问题，间隔10秒重试，最多3次；若仍失败，切换备用TTS工具
    - 本地工具安装失败：检索官方仓库Issues区的Ubuntu适配解决方案，最多重试3次；若仍失败，切换为API类工具

#### 3.3.3 视频素材自动化生成工具
1.  工具选型：核心工具为Remotion（程序化视频生成），配套官方维护的代码高亮、架构图生成、无头渲染相关依赖
2.  安装配置规范：
    - 按Remotion官方文档的Ubuntu系统安装步骤执行，优先使用官方提供的项目初始化命令创建工程
    - 按官方文档补全Chromium无头浏览器的Ubuntu系统依赖，保证无桌面环境也可正常渲染
    - 配置git仓库访问权限，保证可正常克隆目标源码仓库，提取代码片段与项目信息
    - 渲染资源控制：配置Remotion渲染并发数不超过CPU核心数的50%，避免耗尽系统资源
3.  校验标准：可正常初始化示例项目，执行无头渲染命令，成功生成10秒以内的测试视频，视频可正常播放，无画面缺失、渲染报错
4.  错误处理：
    - 安装失败：提取报错信息，检索Remotion官方文档的Ubuntu常见问题页面，补全缺失依赖，最多重试3次
    - 无头渲染失败：按官方提供的Ubuntu无头渲染依赖清单补全依赖，调整渲染参数，最多重试3次；若仍失败，切换为官方推荐的云端渲染方案
    - 素材生成功能异常：检查依赖版本兼容性，按官方文档更换兼容版本，最多重试3次

#### 3.3.4 视频合成与导出工具
1.  工具选型：核心工具为FFmpeg（官方稳定版），可选配套官方支持Ubuntu的开源视频剪辑工具
2.  安装配置规范：
    - 优先从Ubuntu官方源安装FFmpeg，若官方源版本无法满足功能需求，按FFmpeg官方文档的Ubuntu PPA源配置步骤执行，禁止使用非官方PPA源
    - 安装完成后，配置全局环境变量，保证命令可全局调用
3.  校验标准：执行版本命令可正常返回信息，可正常完成测试图片+测试音频的视频合成，合成的视频可正常播放，音画同步
4.  错误处理：安装失败按官方PPA方案补全依赖，最多重试3次；合成失败提取报错信息，检索FFmpeg官方文档调整参数，最多重试3次

### 3.4 环境全局校验与固化
1.  执行目标：确认所有工具链安装完成，功能正常，环境可稳定执行全自动化工作流
2.  操作规范：
    - 按顺序执行每个工具的全功能测试，记录每个工具的版本、安装路径、功能状态
    - 执行从剧本解析到视频合成的全流程小样本测试，确认全链路可正常闭环
    - 生成环境校验报告，记录所有工具的版本、依赖情况、测试结果
3.  校验标准：所有工具功能测试全部通过，全流程小样本测试无报错，可正常生成符合要求的测试视频
4.  错误处理：若有工具测试不通过，回到对应工具的安装配置步骤，排查修复问题后重新校验，直到所有工具全部通过测试

## 四、全自动化工作流分阶段执行规范
Agent必须严格按本章节的阶段顺序执行，每个阶段完成后必须通过校验，方可进入下一阶段；修复错误后支持从失败阶段断点续跑，无需从头执行。

### 4.1 第一阶段：剧本解析与需求拆解
#### 4.1.1 执行目标
读取Markdown教学剧本，拆解为可执行的自动化任务清单，明确每个任务的输入、输出、时长、依赖关系，关联git源码仓库，完成全流程任务编排。

#### 4.1.2 操作规范
1.  剧本读取与格式校验：读取剧本文件，校验Markdown格式合法性，识别剧本中的结构化标签（如[口播]、[动画]、[代码]、[画面]），修复格式异常
2.  任务拆解：按剧本章节，拆解为口播文本提取、口播音频生成、动画素材生成、代码素材生成、画面截图生成、视频合成六大类任务，每个任务明确输入、输出、时长要求、命名规范
3.  源码关联：根据剧本中的代码描述，定位git源码仓库的对应文件、代码行范围，提取代码片段，生成素材生成的输入参数
4.  时序编排：明确所有任务的先后顺序与依赖关系，比如口播音频生成完成后，方可执行音画同步的视频合成任务，生成任务执行时序表

#### 4.1.3 校验标准
任务清单无遗漏，覆盖剧本中所有的口播、动画、代码、画面需求，每个任务的输入输出明确，时序逻辑正确，源码关联准确无误。

#### 4.1.4 错误处理与重试规则
1.  剧本格式解析失败：检索Markdown解析工具的官方文档修复格式问题，最多重试3次；若仍失败，通过大语言模型对剧本进行结构化重排，重新解析
2.  源码关联失败：检查git仓库访问权限与文件路径，修复后最多重试3次；若仍失败，通过大语言模型根据剧本描述生成对应代码片段，作为替代输入
3.  任务拆解遗漏：通过大语言模型对剧本进行二次校验，补充遗漏任务，重新生成任务清单

### 4.2 第二阶段：口播音频自动化生成
#### 4.2.1 执行目标
根据剧本中的[口播]文本，生成符合教学场景的语音音频，按章节拆分，标注时序，保证语音清晰、语速适中、内容与文本完全一致。

#### 4.2.2 操作规范
1.  口播文本预处理：提取每个章节的口播文本，去除格式标签与特殊符号，优化断句，保证语音合成的流畅度
2.  参数配置：按教学视频场景，检索TTS工具官方文档，配置合理的语速、语调、发音人、音频格式（优先44.1kHz采样率的WAV/MP3格式）
3.  批量生成：按章节批量生成口播音频，按「章节号-口播序号-章节名称」的规范命名
4.  内容校验：对每个音频文件进行校验，确认音频时长、内容与口播文本完全一致，无杂音、无丢字、无卡顿

#### 4.2.3 校验标准
所有口播音频生成完成，可正常播放，内容与剧本完全一致，音质清晰，命名规范，时序标注准确。

#### 4.2.4 错误处理与重试规则
1.  音频生成失败：检查文本合规性，检索官方错误码文档定位问题，调整参数后间隔10秒重试，最多3次；若仍失败，切换备用TTS工具
2.  音频内容与文本不符：优化文本断句，调整发音参数，重新生成，最多重试3次
3.  音频文件损坏：检查存储路径权限，重新生成，最多重试3次

### 4.3 第三阶段：视频素材自动化生成
#### 4.3.1 执行目标
根据任务清单，批量生成剧本中所有的动画、代码、画面素材，保证素材内容准确、风格统一、时长与口播匹配、格式符合视频合成要求。

#### 4.3.2 操作规范
1.  全局风格统一：确定所有素材的统一规范，包括分辨率1920*1080、帧率30fps、主色调、字体、背景风格，所有素材必须符合该规范
2.  代码素材生成：根据提取的代码片段，生成代码高亮截图/滚动动画，标注剧本要求的重点代码行，保证代码内容与git源码完全一致，语法高亮正确
3.  架构与画面素材生成：根据剧本描述，生成架构图、流程图、系统界面模拟截图，保证内容逻辑准确，与剧本描述完全一致
4.  动画素材生成：根据剧本中的[动画]描述，生成对应动态动画，控制动画时长、节奏与对应口播音频完全匹配，保证动画逻辑准确、画面流畅
5.  素材导出与归档：所有素材按规范命名，统一导出为PNG（静态）/MP4（动态）格式，按章节分类归档

#### 4.3.3 校验标准
所有素材无遗漏，内容与剧本、源码完全一致，风格统一，格式合规，命名规范，时长与口播匹配，无逻辑错误。

#### 4.3.4 错误处理与重试规则
1.  素材生成失败：提取报错信息，检索对应工具的官方文档，调整参数后重试，最多3次
2.  素材内容逻辑错误：通过大语言模型二次校验素材与剧本的匹配度，修正错误后重新生成，最多3次
3.  动画渲染失败：修复动画逻辑与参数错误，重新渲染，最多3次；若仍失败，执行降级方案，使用静态素材+转场动画替代复杂动画，保证核心内容呈现
4.  代码素材与源码不符：重新从git仓库提取代码片段，校验内容后重新生成，最多3次

### 4.4 第四阶段：视频合成与导出
#### 4.4.1 执行目标
将口播音频、所有视频素材按剧本时序合成，添加合理的转场、背景音乐、字幕，导出完整的教学视频，保证音画同步、画面流畅、音质清晰。

#### 4.4.2 操作规范
1.  时序对齐：根据任务时序表，将素材与对应口播音频精准对齐，保证口播内容与画面完全同步
2.  视频合成：按时序拼接素材与音频，添加自然的转场效果，配置无版权背景音乐（音量低于口播音量，不干扰语音清晰）
3.  字幕生成：根据口播文本自动生成字幕，精准对齐口播时序，字幕样式符合全局风格规范，清晰易读
4.  视频导出：配置导出参数，分辨率1920*1080，帧率30fps，H.264视频编码+AAC音频编码，MP4格式，保证全平台兼容性

#### 4.4.3 校验标准
导出的完整视频可正常播放，音画完全同步，无卡顿、无杂音，字幕与口播一致，内容覆盖剧本所有章节，时长符合预估要求。

#### 4.4.4 错误处理与重试规则
1.  视频合成失败：提取FFmpeg报错信息，检索官方文档调整合成参数，修复素材格式问题，最多重试3次
2.  音画不同步：重新校验口播音频与素材的时序，调整对齐参数，重新合成，最多重试3次
3.  视频文件损坏：检查导出参数与素材完整性，重新导出，最多重试3次
4.  字幕错误：重新校验口播文本与字幕时序，修正后重新生成字幕并合成，最多重试3次

### 4.5 第五阶段：结果校验与交付归档
#### 4.5.1 执行目标
对最终生成的视频进行全量校验，确认完全符合剧本要求，生成交付报告，整理所有源文件与成果文件，完成归档交付。

#### 4.5.2 操作规范
1.  全量内容校验：对照剧本逐章节校验视频的口播内容、画面素材、动画、字幕，确认无遗漏、无错误、无逻辑偏差
2.  技术参数校验：校验视频的分辨率、帧率、时长、音视频编码格式，确认符合规范要求
3.  交付报告生成：包含环境信息、工具链版本、任务执行情况、视频参数、错误处理记录、文件清单
4.  文件归档：按「剧本文件、源码文件、口播音频、素材文件、工程文件、最终视频、交付报告」分类归档，压缩打包，支持保存到指定路径（含Windows挂载路径）

#### 4.5.3 校验标准
视频内容100%符合剧本要求，技术参数合规，交付报告完整，文件归档清晰，全流程可追溯。

#### 4.5.4 错误处理规则
若校验发现内容错误，定位到对应任务阶段，重新执行该阶段任务，修正错误后重新合成视频，再次校验，直到完全符合要求。

## 五、错误处理与重试核心准则
本章节为Agent处理所有错误的通用准则，必须严格遵循，禁止无规则的盲目重试。

### 5.1 错误分级标准
Agent必须先对错误进行分级，再执行对应的处理方案：
1.  轻微错误：不影响核心流程执行，可通过简单重试修复，如网络超时、临时API限流、文件权限临时问题
2.  一般错误：影响单个任务执行，可通过调整参数、更换方案修复，如单个素材生成失败、单个依赖安装失败、单条口播音频生成失败
3.  严重错误：影响整个工作流执行，需要重新搭建环境或更换核心工具，如系统环境损坏、核心工具链安装失败、核心API永久不可用

### 5.2 通用重试准则
1.  所有错误必须先记录完整的错误日志，包括错误发生的阶段、时间、核心描述、报错代码、执行操作、环境信息，禁止无记录的重试
2.  所有重试必须有明确的间隔时间：轻微错误间隔10秒，一般错误间隔30秒，严重错误间隔5分钟，禁止无间隔频繁重试，避免触发限流或系统资源耗尽
3.  差异化重试次数：网络超时、API临时限流类错误最多重试5次（API限流需严格遵循响应头Retry-After的时间间隔）；依赖安装、内容生成、系统操作类错误最多重试3次，禁止无限重试
4.  重试前必须先定位错误根本原因，调整对应参数或方案，禁止无调整的重复重试
5.  若错误导致系统环境不可逆损坏，必须回滚到上一个正常的环境状态，重新执行操作，禁止在损坏的环境中继续执行

### 5.3 分场景错误处理规范
1.  网络相关错误（超时、连接失败、限流）
    - 先检查网络连通性，确认目标地址可正常访问
    - 超时问题：延长超时时间，更换官方镜像源/网络节点，间隔10秒重试
    - API限流问题：按官方限流规则延长重试间隔，降低调用频率，分批执行任务
    - 多次重试后仍失败，切换备用的镜像源、API接口或工具
2.  依赖与环境错误
    - 权限不足：调整用户与目录权限，使用合理的sudo权限，禁止过度授权
    - 依赖缺失：按官方文档补全对应依赖包，重试最多3次
    - 版本冲突：查找官方认可的兼容版本组合，通过虚拟环境隔离，禁止覆盖系统核心依赖
    - 多次重试后仍失败，更换官方推荐的替代安装方案或工具
3.  内容生成错误
    - 输入内容问题：优化输入内容，修复格式错误，重新执行
    - 参数配置问题：按官方文档调整参数，重新执行
    - 多次重试后仍失败，切换备用工具，或执行降级方案，保证核心流程可执行
4.  git与源码相关错误
    - 权限问题：配置SSH密钥/访问令牌，修复后重试
    - 路径问题：检查文件路径、分支、commit号，重新定位后重试
    - 多次重试后仍失败，通过大语言模型根据剧本描述生成替代代码片段，保证流程继续执行

## 六、安全与合规规范
1.  密钥安全：所有API密钥、访问凭证必须通过环境变量配置，禁止硬编码到代码或配置文件中，禁止提交到git仓库
2.  商用授权：所有使用的工具、模型、素材必须提供个人/小团队免费商用授权，禁止使用无明确商用授权的内容用于公开发布
3.  版权规范：生成内容必须原创，背景音乐、字体、素材优先使用无版权可商用的资源，禁止侵权内容
4.  系统安全：禁止执行来源不明的脚本与命令，禁止关闭系统安全机制，所有操作必须来自官方文档的推荐步骤；系统级操作前必须备份对应配置文件，支持回滚
5.  数据安全：所有用户数据、剧本、源码、生成内容必须妥善存储，禁止未经授权的上传与泄露
